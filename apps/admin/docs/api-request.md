# 백엔드 API 요청 사항 (admin)

관리자 페이지 와이어프레임을 만들며 정리한 요청입니다. 아직 확정 스펙이 아니라 **논의 시작점**입니다.

프론트는 `apps/admin/src/mocks/types.ts` 에 목업 타입을 두고 작업 중입니다. 그 파일이 현재 프론트가 가정하는 데이터 모양이므로 같이 봐주세요.

## 먼저 확정이 필요한 3가지

나머지는 나중에 맞춰갈 수 있지만, **이 셋은 지금 정해지지 않으면 프론트에서 우회할 방법이 없습니다.**

### 1. 부분 수정(PATCH)을 열어주세요

```
PATCH /booths/{id}/
{ "is_closed": true }
```

보낸 필드만 반영되고 나머지는 그대로여야 합니다. DRF 는 `partial=True` 로 기본 지원합니다.

**PUT 전체 교체만 제공되면 곤란합니다.** 단일 역할이지만 학생회 여러 명이 각자 폰으로 같은 목록을 봅니다. A 가 상세 화면에서 운영시간을 고치는 동안 B 가 홈에서 마감을 켜면, 전체 객체 PUT 은 한쪽이 다른 쪽 변경을 통째로 덮어씁니다. 축제 당일에 이게 나면 원인 추적이 불가능합니다.

같은 값을 다시 보내도 200 이면 좋겠습니다. 네트워크가 끊겼을 때 재시도가 안전해집니다.

### 2. 공연에 "지금 진행 중"을 서버 시각 기준으로 주세요

공연 목록 응답에 현재 진행 중인 항목이 표시되면 좋겠습니다. **클라이언트 시계로 계산하면 안 됩니다** — 수백 대 학생 폰의 시계가 제각각입니다.

지도 좌표는 픽셀이 아니라 **백분율 float** 로 주세요. 배치도 이미지가 교체돼도 좌표를 다시 안 잡아도 됩니다.

### 3. 공연 지연을 한 번에 처리하는 엔드포인트

```
POST /performances/{id}/delay/
{ "minutes": 10, "cascade": true }
```

공연은 반드시 밀립니다. `cascade` 가 켜지면 같은 날 그 시각 이후 공연을 모두 함께 이동시켜 주세요.

**이게 없으면 프론트가 PATCH 를 N 번 쏴야 하고, 중간에 하나 실패하면 타임라인이 깨진 채로 남습니다.** 축제 당일에 복구할 방법이 없습니다.

## 그 외 요청

### 4. 수정 응답에 갱신된 객체 전체를 담아주세요

프론트는 낙관적 갱신(요청을 보내기 전에 화면을 먼저 바꿈)을 씁니다. 응답에 최종 상태가 오면 화면과 서버가 어긋났는지 바로 확인할 수 있습니다.

### 5. 다국어는 언어 맵으로

한국어·영어·중국어·일본어 4개가 확정 요구입니다. 관리자 API 는 언어 맵으로 주세요.

```json
{ "name": { "ko": "타로 점집", "en": "Tarot Booth", "zh": null, "ja": null } }
```

**사용자 API 는 `?lang=en` 으로 서버에서 fallback 이 적용된 평문**을 주시면 프론트가 훨씬 단순해집니다. 번역이 없으면 한국어로 떨어지면 됩니다.

한국어만 필수이고 나머지는 비어 있을 수 있어야 합니다. 사이트 오픈이 10/6 인데 4개 언어를 다 채우고 오픈하는 건 현실적으로 어렵습니다.

### 6. 공지 팝업에 만료 시각

`popup_expires_at` (nullable datetime). 사용자 API 에서는 만료된 공지를 제외해 주세요.

만료가 없으면 10/7 오후에 올린 긴급 공지가 10/8 저녁까지 떠 있습니다. 아무도 끄러 오지 않습니다.

## 다루는 데이터

`apps/admin/src/mocks/types.ts` 에 정의돼 있습니다. 요약하면 8종입니다.

| 대상      | 주요 필드                                                                     |
| --------- | ----------------------------------------------------------------------------- |
| 부스      | 이름, 주최 단과대, 위치번호, 운영시간, 마감여부, 컨텐츠, 유료 체험(이름+가격) |
| 주점      | 이름, 단과대, 위치번호, 운영시간, 마감여부, 메뉴(이름+가격)                   |
| 푸드트럭  | 이름, 위치번호, 운영시간, 마감여부, 메뉴                                      |
| 공연      | 날짜, 구분(연예인/학우), 출연자, 시작·종료, 무대                              |
| 공지      | 제목, 본문, 긴급여부, 팝업 만료, 게시상태                                     |
| 분실물    | 물품명, 습득 장소·시각, 수령여부                                              |
| 지도 핀   | 종류(부스/주점/푸드트럭/쓰레기통/의무실), 라벨, 위치번호, x·y(%)              |
| 축제 정보 | 이름, 컨셉, 테마, 기간                                                        |

부스 위치는 `spotNumber` 정수 하나로 식별합니다. 지도 핀과 이 번호로 연결됩니다.

## 아직 정해지지 않은 것

- **부스·주점 총 규모** — 부스 협의회 이후 확정
- **지도 배치도 이미지** — 같이 확정
- **연예인 라인업** — 인스타 공개 시점에 입력
- 이번 축제는 동아리 부스가 없습니다. 학생회·단과대 부스만입니다

## 참고: 화면 쪽 결정

- 관리자 화면은 **모바일 폭(430px) 고정**입니다. 축제 당일 현장에서 폰으로 마감을 토글하고 긴급 공지를 올리는 상황을 전제합니다
- 마감 토글은 **확인 없이 즉시 저장**하고 실행취소 토스트를 띄웁니다. 그래서 위 1번(부분 수정)이 필요합니다
- 부스 정보 수정은 학생회가 전담합니다. 부스별 계정 발급은 이번 범위에 없습니다
