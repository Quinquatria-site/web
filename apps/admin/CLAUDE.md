# admin 작업 규칙

## 작업 시작

**항상 `dev` 를 최신으로 맞추고 시작한다.**

```bash
git switch dev
git pull
git switch -c <타입>/admin-<설명>
```

`dev` 가 작업 기준선이다. `main` 에서 브랜치를 따지 않는다.
오래된 `dev` 에서 시작하면 남이 이미 고친 것 위에서 작업하게 되고,
머지 시점에 충돌이 한꺼번에 몰린다.

PR 도 `dev` 로 낸다. `main` 은 릴리즈 때만 받는다.

## 루트 CLAUDE.md 를 수정하지 않는다

루트 `CLAUDE.md` 는 팀 공용 정책이다. admin 담당이 단독으로 편집하지 않는다.

이 파일은 루트를 덮어쓰지 못한다. 루트 규칙 위에 얹힐 뿐이다.
충돌하면 루트가 이긴다. 루트 정책을 바꿔야 하면 직접 고치지 말고 팀에 제안한다.

`apps/user` 와 루트 설정 파일도 같은 이유로 건드리지 않는다.

### 그래도 공통 파일을 고치게 되면

팀이 승인해서 루트나 공유 설정을 수정하게 되면, **브랜치를 파기 전에 원격부터 확인한다.**

```bash
git fetch origin
git rev-list --left-right --count dev...origin/dev
```

로컬 `dev` 가 "up to date" 로 보여도 fetch 전에는 오래된 정보다.
원격이 앞서 있으면 pull 한 뒤에 브랜치를 판다.
다른 팀원이 먼저 고친 것을 오래된 시작점에서 덮어쓰는 사고를 막는다.

## 워크로그

`apps/admin/docs/worklog/<ISO주차>.md` 에 남긴다. 예: `2026-W36.md`
한 주에 파일 하나. 파일 안에서는 최신 항목이 위로 간다.

### 절차

1. 코드를 커밋한다
2. 방금 생긴 해시로 워크로그 항목을 쓴다
3. 워크로그만 따로 커밋한다 — `docs: 워크로그 <해시>`

워크로그 커밋 자체는 기록하지 않는다.
브랜치에 커밋이 여러 개면 항목도 여러 개 쓰되, 워크로그 커밋은 PR 직전에 한 번으로 묶어도 된다.

### 형식

**필수** — 항상 쓴다. 커밋 해시·메시지·날짜·변동사항.
**선택** — 해당될 때만. 없으면 그 줄을 통째로 지운다. "없음" 이라고 쓰지 않는다.

```markdown
## 2026-09-02 · a1b2c3d

**커밋** `feat: 부스 등록 폼 추가`

**변동사항**

- 무엇이 바뀌었는지 목록으로

**결정 근거**
왜 이렇게 했는지. 다른 선택지를 버린 이유까지.

**차후 작업 계획**
이어서 할 것.

**user 전달사항**
user 앱 개발자가 알아야 할 것.

**주의사항**
다음에 밟을 지뢰.

**결정 경위**
대화하며 정해진 것. 어떤 논의 끝에 이 모양이 됐는지.
```

**user 전달사항** 을 썼으면 PR 본문에도 같은 내용을 옮긴다.
이 파일은 `apps/admin` 안에 있어서 user 담당자가 볼 일이 없다.
