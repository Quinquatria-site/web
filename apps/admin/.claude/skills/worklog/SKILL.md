# admin 워크로그 작성

`apps/admin/CLAUDE.md` 의 워크로그 정책을 실행한다.
형식과 절차의 출처는 그 파일이다. 이 스킬과 어긋나면 그 파일이 이긴다.

## 절차

1. 대상 커밋을 확인한다.

   ```bash
   git log -1 --format='%h%n%s%n%ad' --date=short
   ```

   사용자가 다른 커밋을 지정했으면 그것을 쓴다.
   직전 커밋이 워크로그 커밋(`docs: 워크로그 ...`)이면 중단한다 — 워크로그는 자기 자신을 기록하지 않는다.

2. 무엇이 바뀌었는지 읽는다.

   ```bash
   git show --stat <해시>
   ```

   변동사항을 쓰기에 부족하면 `git show <해시>` 로 diff 까지 읽는다.

3. 대상 파일을 정한다.

   ```bash
   python3 -c "import datetime;i=datetime.date.today().isocalendar();print('%d-W%02d'%(i[0],i[1]))"
   ```

   `apps/admin/docs/worklog/<주차>.md` 다. 파일이 없으면 만들고 첫 줄에 `# <주차> (MM-DD ~ MM-DD)` 를 넣는다.

4. 항목을 **파일 맨 위**, H1 바로 아래에 넣는다. 기존 항목을 아래로 민다.

5. 워크로그만 커밋한다.

   ```bash
   git add apps/admin/docs/worklog/
   git commit -m "docs: 워크로그 <해시>"
   ```

   다른 파일을 같이 스테이징하지 않는다.

6. **user 전달사항** 을 채웠으면, 같은 내용을 PR 본문에도 옮기라고 사용자에게 알린다.
   이 파일은 `apps/admin` 안에 있어서 user 담당자가 볼 일이 없다.

## 형식

필수 네 가지는 항상 쓴다.

```markdown
## <YYYY-MM-DD> · <해시 7자리>

**커밋** `<커밋 메시지 제목>`

**변동사항**

- 무엇이 바뀌었는지
```

선택 다섯 가지는 해당될 때만 쓴다.
**해당 없으면 제목 줄까지 통째로 지운다.** "없음", "해당 없음" 이라고 쓰지 않는다.

| 항목 | 쓰는 경우 |
| ---- | --------- |
| **결정 근거** | 선택지를 놓고 고른 게 있을 때. 버린 쪽과 그 이유까지 |
| **차후 작업 계획** | 이어서 할 일이 정해졌을 때 |
| **user 전달사항** | user 앱·공용 설정·API 계약에 영향이 있을 때 |
| **주의사항** | 나중에 밟을 지뢰를 발견했을 때 |
| **결정 경위** | 대화하며 방향이 바뀌거나 정해졌을 때 |

## 규칙

- `git log` 로 알 수 있는 것은 **변동사항** 에 요약만 한다. 나머지 칸은 로그에 안 남는 것만 채운다.
- 커밋 메시지 본문을 그대로 복사하지 않는다.
- 사소한 커밋은 필수 4개로 끝낸다. 억지로 늘리지 않는다.
- **결정 경위** 는 결론만이 아니라 무엇을 버렸는지를 남긴다. 그게 로그에 안 남는 유일한 정보다.
- 코드를 고치지 않는다. 워크로그 파일만 건드린다.
- 루트 `CLAUDE.md` 와 `apps/user` 는 건드리지 않는다.

## 검증

- 항목의 해시가 `git log` 의 실제 해시와 일치하는가
- 항목이 파일 맨 위에 들어갔는가
- 내용이 빈 선택 필드가 남아 있지 않은가
- `git show --stat HEAD` 에 워크로그 파일만 있는가
